# Reference sites — a backbone for learning, not a rule

When a brief says "modern and professional" — or nothing at all — and names
no references, the build starts generic. The fix is not a better adjective.
It is a reference: a real site that already solved the aspect the brief
needs. This file lists ten such sites, one per aspect. It is advisory
only — a backbone to learn from, not a rule to follow.

## The ten sites

| Aspect | Site | What it teaches |
|---|---|---|
| Animations | apple.com | Motion that explains, never decorates |
| Onboarding | duolingo.com | A first-run flow that teaches by doing |
| UI design | linear.app | Dense product UI that stays calm |
| Typography | pentagram.com | Type as the identity |
| Minimalism | muji.com | Restraint as a system |
| Search & filters | airbnb.com | Finding things fast without clutter |
| Art direction | aesop.com | A point of view in every frame |
| Dashboards | notion.com | Information density that stays readable |
| Landing page layouts | stripe.com | Structure that carries the argument |
| Micro-interactions | framer.com | Small responses that make a page feel alive |

## Rules of use

1. Never start from "modern and professional" alone. Name the aspects the
   brief needs, then name the sites that teach them.
2. Take principles, not pixels. Adapt the idea to the brand; never copy a
   site's layout, copy, or assets.
3. One aspect, one teacher. Do not study all ten for every build — study
   the two or three the brief actually needs.
4. If the brief already names references, use those. This list is the
   fallback for a brief with none, not the default.
5. Never mandatory, never a grading input. A build is never failed for not
   using these sites, and using them earns nothing on its own — the gate
   and the grade still judge the build, not the bibliography.
